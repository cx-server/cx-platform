# EmptyState

Placeholder shown when a view has no data or content to display, guiding users toward an action.

## When to use

| Use EmptyState when... | Don't use EmptyState when... |
|---|---|
| A list, table, or section has zero items to show | Data is still loading — use Skeleton instead |
| You want to guide the user to create their first item | An error occurred — use Alert for error messaging |

## Props

| Prop | Type | Default | Description |
|---|---|---|---|
| `id` | `string` | required | Unique identifier (used for `id` and `data-testid`) |
| `title` | `ReactNode` | — | Heading text (rendered as `ArticleHeader`) |
| `description` | `ReactNode` | — | Body text (rendered as `ArticleContent`) |
| `icon` | `ReactElement` | — | Icon element, automatically sized to 72×72px |
| `children` | `ReactNode` | — | Additional content below description (CTAs, links) |
| `className` | `string` | — | Additional classes on the outer container |
| `articleClassName` | `string` | — | Additional classes on the inner Article wrapper |

## Internal structure


## Best practices

### Do
- Include an icon to make the empty view feel intentional
- Provide a clear CTA when the user can resolve the empty state themselves
- Use specific messages — "No bet history" not "No data"

### Don't
- Leave views completely blank
- Use generic messages like "No data" or "Nothing here"
- Stack multiple EmptyStates on one page

## Accessibility
- Uses Article/ArticleHeader for semantic structure
- Icon is decorative (no alt text needed)
- CTA buttons follow standard Button accessibility patterns
